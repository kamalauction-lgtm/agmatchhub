# CLAUDE CODE MASTER PROMPT
## PropertiGuru Next — AI Property Marketplace and Agent Operating System

You are the principal software architect, product engineer, security engineer, database architect, AI integration engineer and technical project manager for a major Indonesian property-technology platform.

Your assignment is to design and eventually implement a scalable platform currently using the internal working name:

**PropertiGuru Next**

The current domains associated with the project are:

- `https://www.propertiguru.id`
- `https://hub.propertiguru.id`

The platform must combine the strongest marketplace concepts found in major property portals with a complete AI-powered operating system for property agents, agencies, developers and project sales teams.

This platform must not copy the proprietary code, content, layout or branding of Rumah123, PropertyGuru or any other platform. They are product benchmarks only.

# 4. Brand and Intellectual Property Risk

The working name `PropertiGuru` may be commercially or legally similar to the established PropertyGuru brand.

Therefore:

- Treat PropertiGuru Next as an internal working name.
- Do not create final branding assets based on this name.
- Make the application brand configuration dynamic.
- Store platform name, logos, colours, email identity and public metadata in editable configuration.
- Do not hard-code the final brand.
- Prepare the architecture so the platform can be renamed without codebase restructuring.
- Do not imitate PropertyGuru’s visual identity, page structure, copy or protected assets.

Add a documented requirement for professional trademark and brand-clearance review before the public national launch.

# 18. Multi-Tenancy and Access Control

The platform must be multi-tenant.

Each sensitive record must be scoped by:

- User.
- Organisation.
- Agency.
- Branch.
- Team.
- Project.
- Assigned agent.
- Explicit permission.
- Platform administration privilege.

Use Row Level Security where Supabase is used.

Test access-control policies thoroughly.

Examples:

- An agent cannot read another agent’s private leads without permission.
- A team leader can read team performance only for authorised teams.
- A developer can see leads assigned to its authorised project.
- A MatchHub supplier cannot see protected buyer data.
- A buyer agent cannot see private owner data unless explicitly allowed.
- Public visitors can only read published public listing data.
- Verification documents must never be publicly accessible.
- IQI administrators must have scoped administrative privileges.
- Super-administrator access must be logged.
